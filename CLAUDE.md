# Secure AI Deployment course

A free, public course on securing AI agents, for engineers who can code but may be new to agents. Interactive marimo notebooks run in the learner's browser (Pyodide/WASM) and are published to GitHub Pages on every push to `master`:
https://1dzl0.github.io/secure-ai-deployment/course/ (the course shell; each module loads in an iframe).

Engines the notebooks import (marimo bundles each as a wheel in the WASM export, so a change reaches every page that imports it):
- `notebooks/koda_lab.py`: the shared lab (mock agent, `dispatch()` policy checkpoint, graders) plus the page helpers `hero`, `mono_panel`, `exercise_html`, `recap_html`, `terms_html`, `divider`, `console_html`; providers and keys (`PROVIDERS`, `has_key`, `key_mismatch`, `post_for`).
- `notebooks/koda_toolbox.py`: Module 03's ten-tool toolbox and its graders.
- `notebooks/koda_practice.py`: the practice pages: in-browser install of the agent SDKs, the HTTP patch, the offline practice model, `run_code`, graders that read the logged HTTP calls.
- `notebooks/koda_retrieval.py`: Module 04's engine: the store and word-overlap retriever, and one function per pipeline stage (ranking knobs, the parser's layers, chunking, assembly with copies and blockers, the answer check, the index lifecycle, write-back, an agent's own searches), with three graded exercises.
- `notebooks/koda_answer.py`: Module 05's engine: the leak grader and its stand-in, the recorded-run reader and writer for `RECORDED["module05"]`, the field allowlist, the redactor, a model of a browser for the renderer, the no-click request policies, the SQLite and template sinks, the prompt audit, and the five graded exercises.
- `notebooks/koda_recorded.py`: `RECORDED` real-model runs replayed when a learner has no key. Generated by `tools/record_live_runs.py`; don't hand-edit.

Older parts, still used: `lab/`, `mock/`, `test_lab.py` (the original command-line lab); the Jupyter versions `notebooks/*.ipynb` (committed with their outputs) are generated by `tools/build_02.py` and `tools/build_04.py` with `notebooks/m04_lab.py`: edit the script and re-run, never the .ipynb. `PLAN.md` is a September 2026 snapshot, not the current plan.

## Commands

Run Python through uv (marimo 0.25.1 needs Python 3.12; the system python is too old):

```
uv run --python 3.12 --with marimo==0.25.1 --with pyyaml python <script>
```

- Self-checks (CI runs these; all must print ok): `python test_lab.py`, `python notebooks/koda_lab.py`, `python notebooks/koda_toolbox.py`, `python notebooks/koda_practice.py`, `python notebooks/koda_answer.py`, `python notebooks/koda_retrieval.py`
- Lint a notebook: `cd notebooks && python -m marimo check <file>.py`
- Runtime errors: `python -m marimo export html <file>.py -o /tmp/x.html` executes every cell; search the output for `application/vnd.marimo+error`. The `html-wasm` export catches neither runtime nor DAG errors.
- Fast regression test without a browser: import the notebook, call `app.run(defs={...})` with `types.SimpleNamespace(value=...)` standing in for any `mo.ui` element (and `page` for the practice pages), turn outputs to text with `marimo._output.formatting.as_html(o).text`.
- Build a page as CI does (always from `notebooks/`, because html-wasm resolves `css_file` against the working directory):
  `cd notebooks && python -m marimo export html-wasm <file>.py -o ../_site/<dir>/index.html --mode run --no-show-code`, then `cp -r course _site/course` and serve `_site` with `python -m http.server`.
- Re-record the no-key replays (costs money, needs a key): `python tools/record_live_runs.py --dry-run` first.

## Conventions

Writing
- No em dashes or en dashes anywhere learners read. Use periods, colons, commas; "2 to 8" for ranges. Check with `grep -n '—\|–'`.
- Sentence case, plain words, at most one bold sentence per section.
- Do not claim more than the lab shows. If a deployment still leaves a gap open, the page says so.

Teaching shape
- Each module teaches one thing, and no material repeats across modules: link to where it is taught instead. Foundations and its practice pages are one unit with their own rule: Module 01 is the main lesson and holds every core idea in short form, and each practice page states what it builds on in a line or two (or shows the same picture, such as `koda_lab.loop_svg`), so a learner never has to go back to Module 01 to follow it. A practice page drills an idea; it does not re-teach it. Links out of a notebook use `target="_top"` (it runs inside the shell's iframe), e.g. `../course/#/practice/1.3`.
- Exercise skeleton: a short lead, `exercise_html(num, title, goal, minutes)`, the control, feedback directly under the control, then an "in a sentence" callout. Exercise numbers read module.part.n. Modules 01, 02 and the practice pages use these helpers (`exercise_html`, `terms_html`, `recap_html`); Module 03 predates them (a local `fb_card` for feedback, `divider` per Part, a "Part N in a sentence" callout) and has not been converted yet; Module 04 uses the helpers with `divider` Parts and "in a sentence" callouts. New modules use the helpers.
- Every page works without an API key. A blank key or `NA` replays `RECORDED` runs, labelled "Recorded on <date>", graded by the same graders as a live run.
- Graders are tested against several correct answers and plausible wrong ones, not only the model answer. The engine self-checks hold those cases; extend them when you add an exercise.

Look
- One accent, `#1d4ed8`, on grey. Status is shown by weight and the glyphs ✓ ✗ ○, never by red/green/amber. No shadows, radius at most 6px.
- Use the `.sad-*` classes and the `koda_lab` helpers; put new styles in `course/course.css`, not inline. Every notebook sets `marimo.App(width="medium", css_file="../course/course.css")`.
- Check at 390px wide: `#App` must not scroll sideways (long code lines, selects and nowrap tags are the usual cause).

## Browser (WASM) limits

- Only top-level cell imports get installed, and plotly does not load: draw charts as inline SVG.
- Pin exact versions of anything installed in the browser (micropip never backtracks; install shared pins first). See `koda_practice.install_core` and `patch_http` for how the OpenAI, Anthropic, LangChain, LangGraph and Agents SDKs are made to run.
- Every `mo.ui` widget renders in a shadow root; `course.css` reaches it only because marimo copies `<style title="marimo...">` into each root.
- Names used in more than one cell must be cell-local (`import json as _json`); a private alias imported in two cells fails `marimo check`.
- `*.html` is gitignored. Course pages are un-ignored by `!course/*.html` and `!course/*/*.html`; a page one level deeper needs its own rule.
- GitHub Pages can serve the previous build for a minute; add `?cb=<anything>` when checking a deploy.

## Boundaries

- Public repo. Never commit `.env`, `config.yaml` or any key; never print a key's value (check presence by name only). Mock secrets stay obviously fake (no `sk_live_`, `AKIA` patterns) so push protection passes.
- Commit only when asked. Push only when the user says push: a push to `master` deploys the live site.
- Don't re-fact-check or rework the case library (`course/cases/`) unless asked.
- `*.html`, `notebooks/assets/`, `notebooks/__marimo__/` and `_site/` are build output, rebuilt in CI; don't commit them.
